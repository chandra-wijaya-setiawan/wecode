# project-purpose — a project states what it is for, and tasks answer to it

The owner's asks, gathered from three conversations and finally written down (the
failure to do this earlier is why stated-intent delivered only a budget advisory):

1. **Declaration.** A project (or its repo's playbook — the design decides which, and
   argues it) states `purpose` — one sentence — and `refuses` — a short list of
   non-goals, the "Not doing" that today lives unread in plan.md. wemail's would say
   it refuses multiple accounts; korean-trip's that it refuses booking.

2. **The challenge is a question, never a verdict.** At `task add`, when a title or
   scope plausibly touches a refusal, admission asks — the way it already asks "which
   paths may this change?" — and the filer's answer is recorded with the task. Wrong
   is possible in both directions, so nothing is auto-refused: a challenge unanswered
   blocks; a challenge answered is a decision on the ledger.

3. **Changing the statement is deliberate.** Editing purpose or refuses is a recorded
   act (`define`, like scope amendments), so drift and decision are distinguishable
   in the ledger — the owner's line: "the owner can change scope, but it must be
   deliberate rather than drifting."

4. **The envelope carries the answer, not the essay.** The filer's one-line
   justification travels with the task; the purpose line rides every envelope for the
   repo. Orchestrators comply because the template demands the field, not because
   they remember.

## Evidence this is needed, all from one week

- I offered a wemail multi-account slice; plan.md's "Not doing" said no; nothing
  challenged me but my own reading.
- wecode-loop's objective was achieved while 60% of its tasks served something else;
  nothing could say so because nothing knew what it was for.
- The one task filed without a brief (stated-intent itself) delivered a narrow
  reading of its title — compliance produces context, memory does not.

- No obligation system (must-update-docs) in this task — related, separately filed
