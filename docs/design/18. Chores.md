# Chores

Work wecode needs done, created deterministically by wecode and performed by a **system
worker**.

**wecode is itself powered by agents.** It does not only dispatch them for your work — it
employs them for its own: merging what would not merge, bringing a stale branch up to date,
summarising what it has learned. The same machinery, pointed inward. That is what makes it
a system with judgement rather than a scheduler with rules.

## Why this is not a task

A task is defined as *work that exists to make one acceptance_test pass*. Merging a story
into the base branch proves no criteria. Summarising twenty lessons into five proves no
criteria. Deploying a release proves no criteria. Forcing each of them to hang off an
acceptance_test would be ceremony and a lie about why the work exists.

But they are still work: they need a worker, a scope, a budget, a worktree and a record —
which is everything an assignment already is.

## What a chore is

| | |
|---|---|
| **created by wecode, never by a person** | a condition became true. Nobody typed anything |
| **performed by a system worker** | the same assignment machinery: scope, budget, worktree, attempts |
| **proved by a check, not a test** | one command that says whether it worked |
| **about a target** | the story it merged, the project it summarised, the release it deployed |
| **sometimes requiring approval before it starts** | a kind may be declared as needing one. Such a chore is created but not `ready`: it waits on `needs_human` of kind `approval`, and only becomes dispatchable when the operator says so |

```
condition becomes true ──► chore created ──► assignment ──► system worker ──► check ──► done

                        └─► if the kind needs approval:
                            chore waits ──► operator notified ──► approved ──► ready
```

**Approval comes before the work, not after it.** A chore that might lose something is not
dispatched and then judged; it is proposed, and nothing happens until somebody says so.
Asking afterwards is asking about a thing that already happened.

## The kinds

| kind | created when | the check | approval |
|---|---|---|---|
| `merge` | a story is delivered and its branch does not merge cleanly into the base | the merge lands and the story's acceptance tests still pass | no |
| `refresh` | the base has moved and a story tree in flight is behind it | the base merges into the story branch and the suite still passes | no |
| `summarise` | a project has more lessons than a brief may carry | the lessons are fewer and the survivors still say what the originals said | no |
| `heal` | a check found drift that cannot be fixed safely — see [19](19.%20Healing.md) | the invariant that was broken now holds | **yes** |
| `sweep` | a collection would remove the only copy of something: a branch of dropped work, a tree with uncommitted files | the thing is gone and nothing else was | **yes** |
| `deploy` | a release is released | whatever the project's deploy check is | **yes** |

Only `merge` and `refresh` are needed now. The list is data, not a switch statement: a kind
is a name, a condition, a role and a check.

## Why a chore needs its own role

A feature task is confined to a handful of files, and must be. **A merge cannot be** — a
conflict is wherever the conflict is. So a chore runs under its own role, with its own
ceiling, and that ceiling is deliberately wider:

| role | worker kind | may write |
|---|---|---|
| `engineer` | agent | the files its task named |
| `system` | **system worker** | anything in the repository, because a conflict does not respect scopes |

A **system worker** is a worker like any other — a role plus a harness — and it is the only
one wecode creates for itself. It appears on the board as itself, and its attempts are
counted, budgeted and killed exactly like an engineer's.

That is the whole reason chores are a separate thing rather than a flag on a task: **they
need authority a task must never have.** Making that visible is worth a noun.

## What it must not become

| | |
|---|---|
| **not a general escape hatch** | a chore kind is declared with its condition. There is no `wecode chore create "do a thing"` |
| **not free of the budget** | a chore holds a slot like anything else. A merge that runs while you are watching three agents is a fourth agent |
| **not silent** | it appears on the board as itself, with its kind and its target, not as a mysterious assignment |
| **not a substitute for rung 1** | wecode still tries the merge itself first. A chore exists for the case where the deterministic attempt failed — `docs/design/14` is unchanged |
