# Plan files

`wecode plan <file.yaml>` — a whole story as one document.

Shaping the cockpit story cost eighteen commands and two id mistakes, each of which wrote
into another project. The structure was entered as a sequence of side effects: nothing was
reviewable until it existed, and a wrong id was already written when it was noticed.

A plan file is the same structure as one artefact — checked whole, created whole, and
diffable afterwards.

## The file declares what it is

The first key names the root, and the rest hangs off it. One command, three shapes, so the
day a plan describes a release nothing has to be renamed.

| root | what the file holds |
|---|---|
| `story:` | requirements, criteria, tests, tasks |
| `epic:` | stories, each with all of the above |
| `release:` | epics, each with stories |

A root that already exists is joined by id; a root that is a sentence is created under its
parent.

```yaml
story: the cockpit is one reusable list at three sizes
epic: 102                      # or omit, and --epic says which

requirements:
  - statement: a box, a box page and a node's children are one list function
    criteria:
      - statement: one function renders rows, columns, a height and a cursor
        test: pnpm exec vitest run packages/tui        # optional
        tasks:
          - title: write packages/tui/src/list.ts as the contract specifies
            scope: [packages/tui/src/list.ts, packages/tui/test/list.test.ts]
            test: pnpm exec vitest run packages/tui/test/list.test.ts
            role: engineer                              # optional
```

| key | required | falls back to |
|---|---|---|
| one of `story`, `epic`, `release` | yes — exactly one | — |
| `epic` | no | `--epic`, then the newest in-progress epic of this project |
| `requirements[].statement` | yes | — |
| `criteria[].statement` | yes | — |
| `criteria[].test` | no | `project.yaml`'s `test` |
| `tasks[].title` | yes | — |
| `tasks[].scope` | no | `project.yaml`'s `source` + `tests` |
| `tasks[].test` | no | `project.yaml`'s `test` |
| `tasks[].role` | no | `engineer` |

## What it does

| | |
|---|---|
| validates the whole file first | an unknown key, a missing statement, a scope that leaves the role's ceiling — all reported together, before a row exists |
| creates in one transaction | a file that fails halfway leaves nothing behind |
| starts everything it created | a chain that needs six `start` commands afterwards is the same ceremony moved |
| delivers each test whose artefact resolves | so a task is `ready` when the file said everything it needed |
| prints the tree it made | ids come back as a shape, not one at a time |

## What it refuses

| | |
|---|---|
| an epic in another project | the same guard `create` has. Ids are global |
| a task with no scope and no `project.yaml` | a task that may change anything is not a task |
| `--dry-run` | prints the tree it would make and creates nothing |

## What it is not

Not a second model. Every row it writes is a row `create` would have written, in the same
order, through the same guards. It is the same eighteen commands, held still long enough to
be read.
