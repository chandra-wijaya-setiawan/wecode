# Worktrees and branching

## Where each level lives

| level | git | why |
|---|---|---|
| **project** | the repository, and its integration branch | one checkout, never handed to an agent |
| **story** | a branch, cut from the integration branch | a criteria is only provable once its tasks are together |
| **task** | a branch, cut from the story branch | so a failed attempt's commits are contained |
| **assignment** | a **worktree**, cut fresh from the task branch tip | a retry is an agent with no memory; it must not inherit a dirty tree |

Plus one more, for verification:

| | |
|---|---|
| **story tree** | one reusable worktree at the story branch tip. Acceptance tests run here, after the tasks they depend on have merged. Reset before each run, never written to by an agent |

## What runs where

| | worktree |
|---|---|
| a task's work | the assignment's own tree |
| a `task_test` | **the same tree** — it exists to prove that attempt, not a clean one |
| an `acceptance_test`, `script` kind | the story tree |
| an `acceptance_test`, `judged` kind | the story tree, with a person or an agent looking at it |
| authoring any test | a task, in its assignment's tree, like any other work |

## The flow

1. `story start` cuts `story/<slug>` from the integration branch.
2. `task start` cuts `task/<slug>` from the story branch.
3. `assignment create` cuts a worktree at the task branch tip.
4. The attempt commits to its task branch. The worktree is released.
5. `task finish` merges the task branch into the story branch — guarded by every task_test `passed`.
6. Acceptance tests run in the story tree.
7. `story delivered` merges the story branch into the integration branch.

## Rules, each one paid for

| rule | what it cost to learn |
|---|---|
| **no worktree at the primary checkout** | the tree holding the integration branch must never be dispatchable. A structural guard, not a policy somebody remembers |
| **never share a worktree between running assignments** | neighbours' edits land under you mid-run, and the run's own result file is contended |
| **a rejected attempt still leaves commits** | so the next assignment cuts from the branch tip and is told what is already there. Silently building on refused work is the failure this prevents |
| **no merge inside a run** | an agent cannot pull the base under itself. Tasks are written in non-overlapping scopes, and the base moves only at step 5 |
| **build output never reaches the diff** | `node_modules/**`, `.venv/**`, `__pycache__/**`, `dist/**`, `.next/**`, `coverage/**` |
| **the dependency cache lives outside the tree** | pnpm's content-addressed store and the `uv`/pip cache are global already. A fresh worktree must cost a link, not an install |

## Why fresh-per-attempt is affordable here

| | Rust | TypeScript · Python |
|---|---|---|
| a fresh tree costs | a full `target/` rebuild — minutes, gigabytes | a link against a warm store — seconds |
| what bounded concurrency | RAM during builds | attention, not the machine |

The Rust version had to reuse trees because cutting one was expensive. That constraint is
gone, and the isolation it was trading away is the thing that makes a retry honest.

## Cleanup

| when | what |
|---|---|
| an attempt is committed | its worktree is released |
| a task is `done` or `dropped` | its branch merges or is deleted; no branch outlives its task |
| a story is `delivered` or `dropped` | its branch and its tree go |
| **never** | a worktree with uncommitted files nobody has seen. It is left, and named on the board |
