# Landing

How work reaches the base branch, and how the base reaches work in flight.

Today: a task branch is merged into its story branch on **every tick, forever**, and a
conflict is caught by the same `catch` as "nothing to do" — so a task that cannot land looks
exactly like one that landed an hour ago. Nothing ever brings the base to a story branch, so
a story cut on Monday fails on Wednesday for a reason that has nothing to do with it.

## Three rungs

The shape recovery already uses: deterministic first, judgement second, a person last.

| rung | who | when |
|---|---|---|
| 1 | the runner, inline | it attempts the merge. Clean is the common case and costs nothing |
| 2 | an **agent**, through an assignment | it conflicted. The agent resolves it in the story tree, and the tests judge the result |
| 3 | the operator | the agent could not. `needs_human`, with the conflict named |

A merge is not special work. It is an objective a worker promises to complete, so it is an
assignment like any other — a scope, a budget, a worktree, a record.

## Two directions, one mechanism

| | when | into |
|---|---|---|
| **work lands** | a story is `delivered` and has no `landed_sha` | the project's base branch |
| **the base flows in** | before acceptance tests run in a story tree, if the base has moved | the story branch |

The second is what stops a story rotting. A branch that never sees the base fails on
somebody else's fix, burns its retries, and says nothing useful.

## What is recorded

| entity | field | |
|---|---|---|
| `story` | `landed_sha` | the commit the base became. Null until it lands |
| `story` | `landed_at` | |
| `assignment` | `objective_type` | widened to `task \| acceptance_test \| task_test \| story` |

**A sha, not a boolean.** `is_merged: true` answers one question; a sha answers three — did
it land, as what, and is the base still that. A boolean also goes stale in silence if a
branch is rewritten, and a sha cannot.

## Rules

| | |
|---|---|
| **merge once** | a task carries the commit it landed as. A tick that sees it recorded does nothing, which is what stops the log repeating `merged 101,102,…` on every line |
| **a conflict is loud** | rung 2 is created, the story stops, and the board says so. It is never the same code path as "already done" |
| **never in the base checkout** | every merge happens in the story tree. The tree holding the base is not something wecode writes to — `wecode land` is the operator's, in their own checkout |
| **tests judge the merge** | a resolved conflict is work like any other: the story's acceptance tests run again on the merged tree before `landed_sha` is set |
| **landing is when a story is done with** | its tree is removed and its branch deleted once `landed_sha` is set. A story tree is never released today, so seven of them stand here holding seven branches that cannot be deleted |

## Cleanup, at the one moment it is safe

| when | what goes |
|---|---|
| an attempt is committed | its worktree — already done |
| `landed_sha` is set | the story tree, then the story branch, then each of its task branches |
| **never** | a tree with uncommitted files nobody has seen. It is left, and named on the board |

Deleting earlier is guessing: before the merge the branch is the only copy of the work, and
a tree released while an agent is in it takes the work with it.
