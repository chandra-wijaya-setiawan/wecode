# Onboarding

`wecode onboard` — what happens when wecode meets a repository.

Before it, starting a project meant hand-writing a test command into every test and a path
into every scope, and retyping both for the next story. The repository already knows all of
it.

## What it does

| step | |
|---|---|
| **detect** | match the repository against `config/stacks.yaml` — a marker file, and the commands that stack uses |
| **record** | write `config/project.yaml`: the test command, the typecheck command, where the source is |
| **register** | create the workspace, the project and its first release |
| **fit** | write `config/roles.yaml` with scopes that are paths this repository has |

It never overwrites a file somebody has edited, and it never guesses when two stacks match —
it says what it found and asks.

## config/stacks.yaml

```yaml
stacks:
  pnpm:
    marker: pnpm-lock.yaml
    test: pnpm exec vitest run
    typecheck: pnpm typecheck
    source: ["src/**", "packages/*/src/**"]
    tests: ["test/**", "packages/*/test/**"]
  npm:
    marker: package-lock.json
    test: npm test
    source: ["src/**"]
    tests: ["test/**", "tests/**"]
  uv:
    marker: pyproject.toml
    test: uv run pytest -q
    source: ["src/**"]
    tests: ["tests/**"]
  pytest:
    marker: requirements.txt
    test: uv run --with pytest pytest -q
    source: ["src/**"]
    tests: ["tests/**"]
  go:
    marker: go.mod
    test: go test ./...
    source: ["**/*.go"]
    tests: ["**/*_test.go"]
  cargo:
    marker: Cargo.toml
    test: cargo test
    source: ["src/**", "crates/*/src/**"]
    tests: ["tests/**"]
```

A stack is four facts and a marker. Adding one is an edit to this file.

## config/project.yaml

What onboarding learned, and what everything else defaults to:

```yaml
stack: pnpm
test: pnpm exec vitest run
typecheck: pnpm typecheck
source: ["src/**", "packages/*/src/**"]
tests: ["test/**", "packages/*/test/**"]
```

| who reads it | for |
|---|---|
| `wecode acceptance_test create` | the default artefact, when none is given |
| `wecode task_test create` | the same |
| `wecode task scope` | the default write scope |
| `wecode onboard` | to refuse to run twice |

## What it does not do

| | |
|---|---|
| scaffold a repository that does not exist | wecode manages work in a repository; creating one is a task like any other |
| guess a test command it did not find | a wrong default is worse than none: every test would pass by running nothing |
| decide what to build | that is the orchestrator's job, and yours |
