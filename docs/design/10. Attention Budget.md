# Attention budget

How many assignments may be open at once, and which one goes next. The allocator is the
only component that reads this.

**The premise:** concurrency is bounded by what one person can attend to, not by what the
machine can run. Eight agents finishing at once is eight diffs nobody reads.

## The config

`config/budget.yaml`, in the workspace.

```yaml
max_open: 3                  # assignments in flight, across the whole workspace
max_open_per_role:
  engineer: 2
  acceptance-tester: 1

order:
  fresh_first: true          # a first attempt goes before a retry
  oldest_first: true         # tie-break

collision:
  scope_overlap: refuse      # two assignments may not hold overlapping write scopes
```

| key | |
|---|---|
| `max_open` | the ceiling. Counts every assignment in `pending`, `running` or `waiting` |
| `max_open_per_role` | optional, per role |
| `order.fresh_first` | a task that has never been attempted goes before one being retried |
| `order.oldest_first` | tie-break, by creation |
| `collision.scope_overlap` | `refuse` — the only value today |

## What counts as open

| phase | holds a slot | why |
|---|---|---|
| `pending` | yes | a worktree is cut and a session is about to start |
| `running` | yes | obviously |
| `waiting` | **yes** | it is waiting on a person, which is exactly the resource being budgeted |
| `succeeded`, `failed` | no | |

`waiting` holding a slot is the rule that makes the budget mean something. A system that
freed the slot would fill the queue with questions nobody has answered.

## The allocator's pass

1. If open assignments ≥ `max_open`, stop.
2. Take every objective that is `ready` — a task, or a test that needs performing.
3. Drop any whose prerequisite has not finished.
4. Drop any whose write scope overlaps an open assignment's.
5. Drop any whose role is at `max_open_per_role`.
6. Order: fresh before retried, then oldest.
7. Create one assignment. Stop, and do the rest on the next tick.

One per tick, deliberately. A pass that fills every slot at once cannot react to what the
first one did.

## Collision

Two assignments collide when their write scopes overlap — `src/api/**` and `src/**` collide;
`src/api/**` and `src/ui/**` do not.

| | |
|---|---|
| overlap is refused, not queued differently | the second waits for the first to finish |
| the check is on **declared** scope | a declared scope is a claim, not a fact. An attempt that writes outside it fails with `out_of_scope`, and that is the check that matters |

## Starvation

A task refused for collision on every pass never runs and nothing says so. So:

| | |
|---|---|
| every refusal is recorded with its reason | the board shows *why nothing is running*, per task |
| a task refused more than N passes in a row is surfaced | not escalated automatically — a person decides whether to narrow a scope or drop something |

## Why not more

Raising `max_open` is the easiest change in this file and usually the wrong one. The
failures it produces are not slow, they are silent: diffs merged unread, questions answered
by pattern rather than thought, and an OOM at 3am that kills the one run that mattered.
