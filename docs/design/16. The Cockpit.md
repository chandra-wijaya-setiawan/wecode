# The cockpit

What `wecode-tui` draws, and why it is laid out rather than printed.

## The lesson that bought this

The Rust cockpit drew its own boxes: `board.rs` reached 1,699 lines of width arithmetic
before it was replaced by declared layout over **taffy**, and the file halved. The part that
was expensive was never the drawing — it was deciding how wide things are.

The TypeScript equivalent is **Ink**: React components laid out by **Yoga**, which is the
same kind of engine taffy is. `<Box>` has borders, padding and flex; `<Text>` has colour.

## What changes, and what does not

| | |
|---|---|
| `config/views.yaml` | **unchanged.** Title, key, filter, rows, columns. It becomes props |
| `app.ts` | **unchanged.** Screens, cursor stack, key map, verbs read off the state machines |
| `list.ts` | becomes a `<List>` component. The truncation, the hidden-row tally and the cursor window survive as they are |
| `screens.ts` | becomes `<Dashboard>`, `<BoxPage>`, `<Node>` and `<KeyBar>` |
| `bin.ts` | renders `<Cockpit>` and feeds `useInput` to `app.key()` |

The state machine and the configuration stay. Only the drawing changes.

## What it must look like

| | |
|---|---|
| every box has a border and a title with its count | `┌─ Queue (3) ─────┐` |
| a box names its key | so `v` then that letter opens it full height |
| the cursor row is inverted, not marked with a character | a gutter character costs a column on every line for one row's sake |
| columns line up down the whole screen | one layout, so a box and its full-height page agree |
| colour carries state, never decoration | failed red, waiting yellow, delivered green, everything else plain |
| the key bar is the last line and drops nothing | a key the bar omits is a screen with no way in |
| nothing wraps | a cell too wide loses its tail to an ellipsis, and a hidden row is counted |

## What it must not do

| | |
|---|---|
| no mouse | a cockpit is a keyboard |
| no animation, no spinner | the board refreshes on a tick; a spinner is a lie about how often anything changes |
| no full-screen alternate buffer until it is worth it | leaving the terminal as it was found matters more than smooth redraws |

## The test has to be able to fail

The first attempt at this was marked done with the dependencies added and nothing else,
because its acceptance test was *the tui suite passes* — which is true whether or not a
single box is drawn.

An acceptance test that cannot fail for the reason the criteria names is not a test. This
one runs the binary and looks for a box-drawing character:

```bash
pnpm -r build && pnpm exec vitest run packages/tui \
  && timeout 4 node packages/tui/dist/bin.js > out.txt 2>&1; grep -q '┌' out.txt
```

Plain text fails it. That is the whole requirement of a test.
