# One Assignment

Every unit of work is allocated the same way, run the same way, and judged the same way.

**On release 0.0.3.** Not started; drawn before implementation so it is not invented twice.

## Why

There are three execution paths where there should be one.

| work | an assignment? | who executes it | budget · scope · lease · retry |
|---|---|---|---|
| a task | yes, by the allocator | foreman | yes |
| a chore | yes, raised then dispatched | foreman | yes |
| **a test run** | **no** | the examiner, `execFile` inline in the tick | **none** |
| **a diagnosis** | **no** | nobody — the doctor only reports | none |

A test run therefore has no timeout of its own, no worker, no record of where it ran, and it
stretches the tick it runs inside. Observed 16–17 Sep: the AST proof timing out under load
(#255); four acceptance tests failing on unbuilt trees (#263); five stalls read as an idle
runner because a slow or refused pass looks like nothing to do.

`ports.ts` already admits `objective_type: "task" | "acceptance_test" | "task_test"`. The
boundary was drawn for this; only the allocator and the adapter were never written.

## The shape

| layer | its one job | what varies by kind |
|---|---|---|
| **allocator** | policy: what is worth starting next, and may it | the candidate query, the role, the collision rule |
| **assignment** | one record: subject, worker, scope, budget, tree, phase | nothing. This is the point |
| **foreman** | make it real: tree, session, liveness, questions, end | the worker adapter |
| **judge** | turn a result into verbs the engine may refuse | examiner for tests, proof for chores |

```
something to do   →   allocator for its kind   →   assignment   →   foreman   →   result
   task                  allocator:sdlc                                          examiner
   test                  allocator:test                                          examiner
   chore                 allocator:chore                                         chore proof
   diagnosis             allocator:diagnosis                                     next doctor pass
   decision              allocator:approval                                      your answer
```

## Allocator, and its policies

One pass, four policies. The pass is written once — at most one assignment per tick, the
budget, the collision rule, and a refusal recorded with a reason for everything it did not
reach.

| policy | candidate | worker | judged by |
|---|---|---|---|
| `allocator:sdlc` | a task `ready` with a ready task_test | agent, by role | examiner |
| `allocator:test` | a test whose verdict does not stand against this tree | script | examiner |
| `allocator:chore` | a chore raised and dispatchable | agent, `system` | chore proof |
| `allocator:diagnosis` | an open violation whose heal is safe | agent, `system` | the next doctor pass |
| `allocator:approval` | a violation or request whose heal is major | **a person** | the answer itself |

## Worker adapters

| | agent | script | person |
|---|---|---|---|
| `instruction` | the prompt | the artefact command | the question |
| `scope` | files it may write | empty — a run writes no source | empty |
| `budget` | tokens and seconds | **seconds only** | none |
| `session` | the harness session | the child process | the assignment itself |
| `resume` | reattach | refused: `failed/lost`, which the port allows | not applicable |
| `answer` | fed back to the agent | never called | the point of it |
| success carries | a commit | output | an answer and who gave it |

## The judge

**A judge is not a worker and is never allocated.** It is called at one place: by
`runner:main`, on an assignment that has just ended, exactly once.

| kind | ended when | judge | verbs |
|---|---|---|---|
| task work | the session finished | examiner, in the tree the agent wrote in | `pass`/`fail` per task_test |
| test run | the command exited | examiner, reading exit code **and** output | `pass`/`fail` |
| chore | the attempt finished | chore judge, re-checking the condition | `finish`/`fail` |
| heal | the system agent finished | none — the next pass decides | none |
| approval | you answered | none — the answer is the verdict | `answer` |

| property | why |
|---|---|
| one call site | a second judgement of one attempt is the bug the run fingerprint exists to prevent |
| a judge creates no assignment | so nothing judges the judge |
| a judge writes no state directly | it calls `engine.apply`; a guard may refuse, and a refusal is never a pass |

## Runner components after the split

| component | modules | owns |
|---|---|---|
| `runner:main` | `main/tick`, `main/record` | the order of one pass, and the record of what it did |
| `runner:allocator` | `allocator/pass`, `allocator/sdlc`, `allocator/test`, `allocator/chore`, `allocator/diagnosis` | what starts next, and why nothing did |
| `runner:foreman` | `foreman`, `ports` | an assignment made real |
| `runner:trees` | `git` | branches and worktrees — the one place two components can collide |
| `runner:judge` | `examiner`, `judge/chore` | a result turned into verbs |
| `runner:doctor` | `doctor/checks`, `doctor/pass` | the record against the world. Writes violations, nothing else |
| `runner:healer` | `healer` | a violation turned into work, or into a question for you |
| `runner:worker adapter` | `adapters/claude-code`, `adapters/script`, `adapters/person`, `adapters/denials` | the only thing that knows a harness from a process from a person |

**Order is a real concern and stays in `runner:main`.** Red-at-base before work; chores
raised then performed; drift named after enforcement; the doctor last and read-only. Its
only permitted dependency is downward: it holds sequence, never logic.

## Invariants

| |
|---|
| every unit of work that runs is an assignment: nothing is executed inside the tick |
| an assignment is judged once, by the judge for its kind, at one call site |
| a judge applies verbs through the engine and never writes a state |
| a test's verdict names the tree it was taken in, and the worker that took it |
| a script assignment carries a timeout, and a kill is `failed/timeout`, not silence |
| `runner:doctor` has no path to the engine or to the trees |

## What this is not

| |
|---|
| **not four allocators.** One pass, several policies — the differences are a query and a role |
| **not a new executor.** The foreman is untouched; the adapters below it grow by two |
| **not a change to what a proof means.** The examiner keeps every rule it has: matched-no-test fails, a missing script is unrunnable, a refused transition is never a pass |
| **not a queue service.** One assignment per tick stays the rule; parallelism comes from `max_open`, as today |

## Migration

| slice | why this order |
|---|---|
| 1. `runner:trees` as its own component | smallest, and the only place five stalls happened |
| 2. `allocator:test` + `adapters/script` | the abstraction itself, against a port that already fits, and it fixes #255 |
| 3. `runner:main` split, `synchroniser` renamed | the file that grows unless the seams exist first (#268) |
| 4. violations, per `21. Health.md` | the doctor gains a place to write |
| 5. `allocator:diagnosis` + `runner:healer` | healing becomes work, gated like work |

## Leans on

Parnas, *On the Criteria To Be Used in Decomposing Systems into Modules* — what varies by
kind is hidden behind what does not. Kubernetes — every unit of work, whatever created it,
becomes one object that one thing executes, reconciled level-triggered rather than on
events. Cockburn, ports and adapters — the worker adapter is the port that keeps a harness,
a process and a person interchangeable above it.
