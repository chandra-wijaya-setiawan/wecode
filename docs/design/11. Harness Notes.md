# Harness notes

What one adapter has to know, and nothing above it does. Checked on this machine,
Sep 2026 — Claude Code 2.1.268, codex-cli 0.151.0.

## Control

| verb | Claude Code | Codex |
|---|---|---|
| start | `claude -p "<task>" --output-format stream-json --verbose` | `codex exec` |
| watch | the `stream-json` lines on stdout | app-server events |
| answer mid-run | `--input-format stream-json`, or `--resume <id> -p "<answer>"` | `codex queue` |
| kill | `claude stop <id>`, with `--bg` | kill the process |
| resume | `--resume <session-id>` | `codex resume` |

**Neither has a pause.** A pause is a kill and a resume, which works only because the
session id is kept beside the assignment.

**Neither speaks A2A.** Codex exposes itself over MCP (`codex mcp-server`); Claude Code
exposes `stream-json` over stdio. A2A is the model here, not the wire.

**A tool name the harness does not recognise is not an error.** It is a permission gate
that refuses every edit and says nothing. The first live run wrote the file twice, was
blocked twice, exited 0, and left an empty worktree.

## What a clean exit means

Exit 0 means the session ended, not that the work is done. The first live run ended
`end_turn` with the work not done and the task correctly stayed `ready` — the test decides,
which is the whole design.

So **every attempt counts against the retry limit, whatever phase it ended in.** Counting
only failures lets a task be retried forever.

## Where a test runs

| | |
|---|---|
| `task_test` | the attempt's own worktree, before the tree is released. It proves *that* attempt |
| `acceptance_test` | the story tree, after the tasks have merged. It proves a criteria |

Both were briefly run at the repository root, which failed a test whose work was three
directories away.
