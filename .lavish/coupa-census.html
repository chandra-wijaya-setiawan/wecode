The rate limit, measured

Coupa never answered 429 and never sent Retry-After. It throttles by stalling, then dropping connections.

concurrencyrequests/srows/smedian latencyoutcome
10.45230.83 sclean
20.87431.07 sclean — scales linearly
40.19109.34 scollapses — 20× slower per request
80.26131.80 s3 of 24 connections reset
Two is the ceiling. Past it the tenant does not reject you politely — it holds requests open, then resets the socket. So the loader caps concurrency at 2 in config, and treats ConnectionResetError as backpressure to back off from, never as a crash. Anything that retries a reset immediately will make the run slower, not faster.

What we cannot reach yet

403 — exists, credential not scoped

  • receipts
  • catalogs
  • attachments
  • locales

These are grants, not absences. The extract client's token comes back with scope: null while the tenant catalogue lists ~190 scopes.

404 — not a top-level endpoint

43 names, including payments, invoice_lines, order_lines, asns, budgets, sourcing_events, webhooks, data_tables. Most are either nested under a parent (/api/invoices/<id>/lines) or named differently in this release. Worth one pass against the API reference for your version before concluding the data isn't there.

Attachments are reachable — once scoped. The 403 (not 404) says the route exists. Attachments hang off their parent, so core.invoice.read and friends unlock /api/invoices/<id>/attachments. Budget for it separately: one request per file at ~0.9 req/s means 10,000 files is about three hours on its own, which is why the files are stored content-addressed so a resumed run never fetches one twice.
